# 页面与交互流程

## 页面列表

第一版 Mission Control 已有五个识别主流程页面，Product Core Foundation 增加 Projects-first 的两个页面：

- 首页
- Projects 页
- Project Workspace 页
- 进度页
- 结果页
- 历史记录页
- 系统状态页

另有一个错误状态视图，可以作为进度页或结果页的一部分实现。

## 页面深浅比例

Formula Lab 采用 SpaceX-inspired 黑白任务控制台，但不是所有区域都强制纯黑。

页面策略：

- 首页：深色任务控制台，突出上传指令区和模型状态。
- Projects 页：深色项目索引，突出论文项目、最近更新和进入工作区。
- Project Workspace 页：深色项目工作台，突出项目指标、批次和公式条目。
- 进度页：深色 launch sequence，突出阶段推进。
- 结果页：深色 LaTeX 控制台 + 白底公式渲染预览。
- 历史记录页：深色 mission log，记录项内部可使用浅色公式预览区域。
- 系统状态页：深色 telemetry，突出服务连通性和模型状态。

这个比例能保留 SpaceX 气质，同时保证 LaTeX 和公式预览的可读性。

## 全局导航

Formula Lab 采用 SpaceX-inspired 顶部导航任务控制台结构，不采用左侧侧边栏。

顶部导航包含：

- 左侧品牌区：`FORMULA LAB`。
- 中间导航：`WORKBENCH`、`PROJECTS`、`HISTORY`、`SYSTEM STATUS`。
- 右侧操作：`UPLOAD`、模型状态。

顶部导航的目标是让用户一进入页面就能看到核心功能，同时保留任务控制台气质。技术架构信息不直接堆在用户界面上，只有系统状态页用于展示 Docker、PostgreSQL、Redis、Celery 和识别模型的可用状态。

## 首页

首页是用户进入系统后的任务控制台，也是第一屏核心体验。

核心元素：

- 产品名称：Formula Lab Mission Control。
- 上传区域：支持点击选择和拖拽上传。
- 图片格式提示。
- 最近任务入口。
- 历史记录入口。
- 模型状态摘要。
- 最近识别任务。

首页不做大段说明文字，重点是让用户立刻知道可以上传公式图片。布局建议采用两栏任务控制台：

```text
左侧主区域：项目路由、上传指令区、图片预览、START RECOGNITION
右侧辅助区域：模型状态、队列状态、最近任务
下方区域：最近任务日志
```

mission 只在用户点击 `START RECOGNITION` 时创建。用户选择或拖拽图片后，页面只进入预览状态。

如果用户选择 Existing Project，系统会为这次上传创建一个 `BatchMission`，并把 `FormulaJob` 关联到对应 `PaperProject` 与 `BatchMission`。如果用户输入 New Project，系统会先创建 `PaperProject`，再创建批次和任务。识别成功后，Celery Worker 会自动把结果沉淀为 `FormulaItem`，Project Workspace 因此能立即展示 LaTeX Preview 与 Paper Preview。

## Projects 页

Projects 页是 Product Core Foundation 的第一入口，用于从“单次识别任务”过渡到“论文项目管理”。

核心元素：

- 项目列表，按最近更新排序。
- 项目名称、Project Code、写作目标和默认导出格式。
- 项目下批次数、公式条目数、待审核数和可导出数。
- 空状态，提示创建或等待项目数据接入。
- 进入 Project Workspace 的操作。

这一页只负责 Projects-first 的项目索引，不实现 Crop Studio、导出文件或本地 LLM。

## Project Workspace 页

Project Workspace 是一个项目的轻量工作区，承接 `PaperProject -> BatchMission -> FormulaItem` 的第一片页面能力。

核心元素：

- 项目概览指标。
- Recent Batches。
- Formula Items 列表。
- Needs Review 与 Ready to Export 的计数或分区。
- Formula Items 的 LaTeX Source 与 KaTeX Preview。
- Paper Preview，用 HTML 先模拟论文页面中的公式排版。
- Symbol Intelligence 占位区，明确为后续阶段。

第一片展示项目、批次、公式条目和即时预览。Paper Preview 先采用 HTML 快速预览，不在普通请求里编译 PDF。Review Drawer、Crop Studio、PDF 导出和本地 LLM 不在本阶段实现。

## 进度页

上传成功后进入进度页。进度页应像任务发射序列，而不是普通 loading 页面。

核心元素：

- 原始图片预览。
- 用户可读 Mission Code，而不是完整 UUID。
- 当前阶段说明，例如 `MODEL WARMUP`、`INFERENCE`、`RESULT READY`。
- 进度条。
- 状态徽标。
- 如果失败，展示错误原因。

前端每隔固定时间请求：

```text
GET /api/missions/<uuid>/
```

当 API 返回 `succeeded` 且进度为 100 时，页面自动跳转到结果页。

## 结果页

结果页是产品体验的核心。

核心元素：

- 原始公式图片。
- 识别出的 LaTeX 文本。
- 一键复制按钮。
- 网页公式渲染预览。
- 任务元数据。
- 返回首页按钮。
- 查看历史按钮。

LaTeX 源码区域使用深色控制台面板，公式渲染预览使用白底或高可读浅色区域。LaTeX 渲染建议使用 KaTeX。页面应同时展示“可复制文本”和“公式效果”，满足课程提升点要求。

LaTeX 控制台默认选中 `BLOCK` tab。用户可以切换 `RAW`、`BLOCK`、`INLINE`，`COPY` 和渲染预览随当前 tab 更新。

## 历史记录页

历史记录页用于展示所有识别任务，视觉上应像 mission log。

每条记录应包含：

- Mission Code。
- 图片缩略图。
- 任务状态。
- LaTeX 摘要。
- 创建时间。
- 识别耗时。
- 查看结果按钮。
- 复制按钮。

每条记录默认只展示总耗时。用户展开记录后，可以看到 `model_warmup_ms`、`image_preprocess_ms`、`inference_ms`、`latex_postprocess_ms` 等阶段耗时。

失败任务显示 `RETRY MISSION`。点击后创建新的 mission，并直接跳转到新 mission 的进度页。

历史记录页应支持空状态。当没有任何任务时，展示一个清晰的上传入口。

## 系统状态页

系统状态页用于开发和验收时排查问题，不作为普通用户主流程。

它应像 telemetry 页面，展示：

- Django Web 是否可访问。
- PostgreSQL 是否连接成功。
- Redis 是否连接成功。
- Celery worker 是否在线。
- 当前识别模型是否可加载。
- 最近一次识别任务是否成功。
- `WARMUP MODEL` 操作。

这个页面可以帮助快速判断问题属于页面、数据库、队列、worker 还是模型依赖。

`WARMUP MODEL` 只出现在系统状态页，不放在 Landing 或 Workbench。

## 交互原则

Formula Lab 的交互应遵循：

- 上传后立即给出反馈。
- 进度状态用后端数据驱动。
- 成功结果容易复制。
- 错误信息清楚，不让用户猜。
- 页面信息密度适中，避免课程作业感过重。
- 顶部导航保持克制，不把技术标签堆在主界面。
- 图标按钮和文字按钮各司其职，复制、重新识别、查看历史等高频动作要明显。
- 不让 SpaceX 气质压过实际工具可用性。
