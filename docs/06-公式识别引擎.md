# 公式识别引擎

## 技术选择

第一版选择 pix2tex / LaTeX-OCR 作为真实公式识别引擎。

选择原因：

- 目标与项目高度匹配：公式图片转 LaTeX。
- Python 生态可用，适合 Django 与 Celery 集成。
- 能体现真实模型识别能力，而不是只对测试图片做映射。

## 识别层边界

pix2tex 不直接写在 Django view 中，而是封装在服务层。

建议结构：

```text
services/
  recognizer.py
  pix2tex_engine.py
  preprocessing.py
  latex_postprocess.py
```

业务代码只调用统一接口：

```python
latex = recognizer.recognize(image_path)
```

这样可以让 Web 层、任务层和模型层保持解耦。

## recognizer.py

`recognizer.py` 是识别入口。

职责：

- 接收图片路径。
- 调用图片预处理。
- 调用具体识别引擎。
- 调用 LaTeX 后处理。
- 返回最终 LaTeX 文本。

它不关心 HTTP 请求，也不直接操作页面。

## pix2tex_engine.py

`pix2tex_engine.py` 是 pix2tex 适配器。

职责：

- 初始化 pix2tex 模型。
- 管理模型加载。
- 对单张图片执行识别。
- 将第三方库异常转换为项目内部错误。

模型加载可能较慢，因此 worker 启动后可以采用懒加载策略：第一次识别时加载模型，后续任务复用同一个模型对象。

## preprocessing.py

图片预处理负责提高识别稳定性。

第一版可以包含：

- 检查图片格式。
- 转换为 RGB。
- 处理透明背景。
- 限制过大图片尺寸。
- 保存预处理后的临时文件。

预处理不应改变用户上传的原始图片，原始图片仍然保留用于结果展示和历史记录。

## latex_postprocess.py

LaTeX 后处理负责让结果更适合网页展示和复制。

第一版可以包含：

- 去除多余空白。
- 去除不必要的外层 `$` 或 `$$`。
- 修正常见换行。
- 保留适合 KaTeX 渲染的纯公式内容。

结果页展示时可以同时提供：

```text
纯公式内容：\frac{a}{b}
Markdown 块公式：$$\frac{a}{b}$$
```

## 模型风险

pix2tex 依赖较重，可能涉及 PyTorch、模型权重、图片处理库和网络下载。

第一版必须把模型风险隔离在 worker 和识别服务层。即使模型依赖出错，Django 页面也应能打开，历史记录页也应能展示失败任务。

错误信息应可见、可解释，而不是让整个网站崩溃。
