# 测试与验收标准

## 课程验收标准

项目必须满足大实验 2 的课程要求：

- Ubuntu 22.04 环境可运行。
- 使用 Python 3.10 与 Django。
- 网站可在 Firefox 中打开。
- 可以上传“测试用图片”中的公式图片。
- 可以转换为 LaTeX 公式文本。
- LaTeX 文本可以复制。
- 页面中可以直接看到公式渲染效果。
- 进度条可以跟随后端任务状态推进。

## 产品级验收标准

除课程要求外，Formula Lab 第一版还应满足：

- Docker Compose 一条命令启动主要服务。
- 本机开发可通过 `make local` 一条命令启动 Redis、Django 和 Celery。
- PostgreSQL 能保存历史任务。
- Redis 与 Celery 可以正常处理后台任务。
- 识别失败时页面不崩溃。
- 历史记录页能看到成功和失败任务。
- 结果页能显示原图、LaTeX 和公式预览。
- 结果页能显示低权重 Paper Fit Preview，且不遮挡 KaTeX Preview 与 LaTeX Source。
- Project Workspace 能展示公式队列、Inspector、Workflow Status、Review Drawer 和项目级导出入口。
- 复制按钮有明确成功反馈。

## 手动验收流程

建议按以下流程验收：

1. 本机开发优先执行 `make local`；Linux 验收再执行 `docker compose up --build`。
2. 打开 `http://127.0.0.1:8000/` 或 `http://localhost:8000/`。
3. 上传 `linux2026/大实验2/测试用图片/formular1.png`。
4. 检查是否进入进度页。
5. 观察进度条是否变化。
6. 等待跳转结果页。
7. 检查 LaTeX 文本是否出现。
8. 检查网页中公式是否渲染。
9. 点击复制按钮。
10. 打开历史记录页，确认本次任务存在。
11. 再上传其他测试图片，确认流程稳定。

## 自动化测试建议

当前自动化测试应覆盖：

- `FormulaJob` 模型状态方法。
- `PaperProject`、`BatchMission`、`FormulaItem` 的项目层关系。
- 上传接口创建任务。
- 任务状态 API 返回格式。
- 失败任务错误信息保存。
- LaTeX 后处理函数。
- Project Workspace 的筛选、分页、Review Drawer hook、Paper Fit hook 和导出链接。
- Mission Report 的 LaTeX formats、KaTeX Preview hook、复制按钮和 Paper Fit Preview hook。
- Workbench 的上传表单、项目路由和遥测上下文。

如果时间允许，可以增加浏览器级测试：

- 首页可访问。
- 上传后跳转进度页。
- 历史记录页可访问。

## Playwright E2E

第一版 Playwright E2E 使用真实公式识别模型，不使用 mock。本机默认模型为 PaddleOCR Formula Recognition。

默认测试四张课程图片：

```text
linux2026/大实验2/测试用图片/formular1.png
linux2026/大实验2/测试用图片/formular2.png
linux2026/大实验2/测试用图片/formular3.png
linux2026/大实验2/测试用图片/formular4.png
```

`make verify` 只做健康检查，不运行真实模型 E2E。真实模型端到端测试通过 `make e2e` 单独执行，测试前可以先运行 `make warmup`。

## 当前常用验证命令

日常开发建议分层验证：

```bash
make frontend-check
./.conda/bin/python manage.py test tests.formulas -v 2
./.conda/bin/python scripts/check_repository_governance.py
```

针对 UI 与页面工作流的快速回归：

```bash
./.conda/bin/python manage.py test \
  tests.formulas.views.test_project_views \
  tests.formulas.views.test_mission_views \
  tests.formulas.views.test_workbench_views \
  -v 2
```

`make frontend-check` 会复制本地 KaTeX vendor 文件，并重新构建 `frontend/formulas/layout_intelligence.js` 到 `apps/formulas/static/formulas/js/generated/layout-intelligence.js`。如果只改 Django 后端，不一定需要每次都跑前端构建；如果改了 `frontend/`、KaTeX vendor、页面 JS 或 CSS，则必须运行。

## 风险检查

实现完成后需要重点检查：

- PaddleOCR 模型是否能在本机 worker 中正常加载。
- pix2tex 对照路径是否仍可启动。
- 模型权重是否能缓存。
- Mac 与 Ubuntu 上 Docker Compose 行为是否一致。
- 上传图片路径在容器内是否可读。
- KaTeX 是否能正确渲染识别结果。
- 进度页轮询是否能在任务失败时停止。
- Pretext layout intelligence bundle 是否重新构建。
- 大 CSS/JS 文件是否继续膨胀，是否触发 repository governance checker。
