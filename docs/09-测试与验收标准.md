# 测试与验收标准

## 课程验收标准

项目必须满足大实验 2 的课程要求：

- Ubuntu 22.04 环境可运行。
- 使用 Python 3.10 与 Django。
- 网站可在 Firefox 中打开。
- 可以上传“测试用图片”中的公式图片。
- 可以转换为 LaTeX 公式文本。
- LaTeX 文本可以复制。
- 页面中可以直接看到公式渲染效果。
- 进度条可以跟随后端任务状态推进。

## 产品级验收标准

除课程要求外，Formula Lab 第一版还应满足：

- Docker Compose 一条命令启动主要服务。
- PostgreSQL 能保存历史任务。
- Redis 与 Celery 可以正常处理后台任务。
- 识别失败时页面不崩溃。
- 历史记录页能看到成功和失败任务。
- 结果页能显示原图、LaTeX 和公式预览。
- 复制按钮有明确成功反馈。

## 手动验收流程

建议按以下流程验收：

1. 执行 `docker compose up --build`。
2. 打开 `http://localhost:8000/`。
3. 上传 `linux2026/大实验2/测试用图片/formular1.png`。
4. 检查是否进入进度页。
5. 观察进度条是否变化。
6. 等待跳转结果页。
7. 检查 LaTeX 文本是否出现。
8. 检查网页中公式是否渲染。
9. 点击复制按钮。
10. 打开历史记录页，确认本次任务存在。
11. 再上传其他测试图片，确认流程稳定。

## 自动化测试建议

第一版至少应覆盖：

- `FormulaJob` 模型状态方法。
- 上传接口创建任务。
- 任务状态 API 返回格式。
- 失败任务错误信息保存。
- LaTeX 后处理函数。

如果时间允许，可以增加浏览器级测试：

- 首页可访问。
- 上传后跳转进度页。
- 历史记录页可访问。

## Playwright E2E

第一版 Playwright E2E 使用真实 pix2tex 模型，不使用 mock。

默认测试四张课程图片：

```text
linux2026/大实验2/测试用图片/formular1.png
linux2026/大实验2/测试用图片/formular2.png
linux2026/大实验2/测试用图片/formular3.png
linux2026/大实验2/测试用图片/formular4.png
```

`make verify` 只做健康检查，不运行真实模型 E2E。真实模型端到端测试通过 `make e2e` 单独执行，测试前可以先运行 `make warmup`。

## 风险检查

实现完成后需要重点检查：

- pix2tex 模型是否能在 Docker worker 中正常加载。
- 模型权重是否能缓存。
- Mac 与 Ubuntu 上 Docker Compose 行为是否一致。
- 上传图片路径在容器内是否可读。
- KaTeX 是否能正确渲染识别结果。
- 进度页轮询是否能在任务失败时停止。
