## Docker Compose 验证

注意：PaddlePaddle 3.3.1 没有 Linux ARM64 wheel，Compose 已固定 `platform: linux/amd64`。Apple Silicon Mac 可以验证部署路径，但构建和运行速度会明显慢于 `.conda` 本机模式。

注意：Compose 内部数据库地址仍是 `db:5432`，但宿主机调试端口默认映射为 `5433`，避免和本机已有 PostgreSQL 抢占 `5432`。如需覆盖，设置 `POSTGRES_HOST_PORT=5432`。

注意：Docker 默认只安装 Paddle 部署路径。`pix2tex`、`torch`、`torchvision` 已拆到 `requirements-pix2tex.txt`，只用于本机可选对照，不参与默认 Linux Compose 镜像构建。

构建：

```bash
docker compose build
```

启动：

```bash
docker compose up
```

Expected services:

```text
web
worker
model-api
redis
db
```

检查：

```bash
docker compose ps
docker compose logs -f model-api
docker compose logs -f worker
```

浏览器打开：

```text
http://127.0.0.1:8000/
```

## Linux 部署验收

Linux 机器需要具备：

```text
Docker
Docker Compose plugin
Git
```

部署步骤：

```bash
git clone https://github.com/Timcai06/LinuxWeek11-Django-FormulaLab.git
cd LinuxWeek11-Django-FormulaLab
cp .env.example .env
docker compose up --build
```

如果 Linux 机器只在服务器内网访问：

```text
http://服务器IP:8000/
```

如果端口没有开放，需要检查：

```bash
docker compose ps
sudo ufw status
```

## 失败回滚

### FastAPI 模型服务回滚

设置：

```text
FORMULA_LAB_RECOGNITION_BACKEND=local
```

效果：

```text
Celery worker 重新使用本地 Paddle 调用链
FastAPI model-api 可以临时不启动
```

### React 编辑器岛回滚

模板保留原 Django 渲染区域。React 加载失败时：

```text
用户仍能看到 FormulaItem 基本信息
用户仍能进入 report/history/system
```

第一版 React island 不应删除现有 Project Workspace 的核心服务端渲染能力。
